Behaviour read from `src/UI/PresetBrowser.cpp` and JUCE 9.0.0 `juce_PopupMenu` at planning time (2026-10-25, HEAD 91c0f30). Every rule the docs state must match this:
- `showMenu` walks `entries` in order and starts a new submenu each time `category` differs from the previous entry's (cpp L212-218). A category that appears in two separate runs becomes two submenus.
- A separator is added before the first non-factory entry in a submenu that already holds a factory entry (L220-222). Interleaved factory and user entries therefore get one separator in the wrong place.
- A submenu is added only if its category is non-empty (L205), so entries with an empty category are never shown.
- Each item ID is `originalIndex + 1` (L225). JUCE's `PopupMenu::addItem` asserts in Debug on ID 0 (`juce_PopupMenu.cpp:1931`), and the result callback calls `onSelect (result - 1)` only for `result > 0` (L259-260): an `originalIndex` of -1 asserts in Debug, any negative index cannot be picked, and dismissing the menu calls nothing. Two entries with the same `originalIndex` report the same pick.
- The item whose `originalIndex == currentIndex` is ticked (L224); a value no entry uses ticks nothing.
- If no entry has the category `"User"` (exact comparison, L236-246), a `"User"` submenu with one disabled `"(empty)"` item is appended.
- `showMenuAsync` returns at once; the callback lambda captures only a copy of `onSelect` (L257), not `this`. JUCE's popup window copies each item (`ItemComponent` holds an `Item` by value), and `PopupMenu::Options` holds the target component and the menu's look-and-feel through `WeakReference`s (`juce_PopupMenu.h:662`, `:1069`). `showMenu` does not use `withDeletionCheck`, so the menu is not dismissed when the consumer's editor is deleted.
- `PresetSaveOverlay::show` sets the text, borrows the parent's look-and-feel, sizes and centres the card on the parent's screen bounds, `addToDesktop` (temporary window with drop shadow), always-on-top, `enterModalState (true)` (non-blocking), selects the text (L70-98). Save and Return call `onSave (trimmed text)` only when the trimmed text is non-empty, then `dismiss()` (L38-60). Cancel, Escape (`keyPressed`) and a click outside (`inputAttemptWhenModal`) call `dismiss()` without `onSave` (L66, L170-184). No other validation exists and nothing is written to disk. `showForSnapshot` adds the card as a child of the parent instead (L100-118).
- The only in-repo user is `tests/UI/FontProvenanceTests.cpp` (it paints a `PresetSaveOverlay`), compiled into `SpatialCoreUITests`: 18 TEST_CASEs in `tests/UI/`, one hidden (`[.][ui-capture]`), so a plain run executes 17.
