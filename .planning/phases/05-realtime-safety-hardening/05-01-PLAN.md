Step 2 — `tests/Support/rtguard/RTGuard.cpp` (new; compiled only into the shared library
`SpatialCoreRTGuard`). Implement RESEARCH "Code Examples: Lock-trap shared library" with these
exact exported `extern "C"` functions: `void scrt_reset()` (zeroes the three counters and forgets
the first offender), `void scrt_arm()` (installs the hook into libmalloc's `malloc_logger` SPI
pointer, declared `extern "C"` with the `malloc_logger_t` typedef from the research, if not yet
installed, then stores `pthread_self()` into an `std::atomic<pthread_t>` armed-thread id; it does
NOT reset the counters, so several armed blocks accumulate), `void scrt_disarm()` (stores a null
thread id), `int scrt_allocs()`, `int scrt_frees()`, `int scrt_locks()`, and
`void scrt_print_first_offender()` (writes the stack captured at the first counted allocation since
the last reset to stderr with `backtrace_symbols_fd`; prints a one-line "no allocation captured"
when there is none). The hook counts only when the armed id equals `pthread_self()`; the type bit
`2` counts an allocation and `4` a free (realloc 0xe counts both, calloc 0x4a counts one
allocation). On the first counted allocation after a reset it clears the armed id, calls
`backtrace()` into a preallocated `void*` array of 64 frames, stores the frame count and re-arms,
so the capture never recurses into the hook. No `thread_local`, no logging and no allocation
inside the hook (Pitfall 1). The lock trap is a `__DATA,__interpose` table in this same library
redirecting `pthread_mutex_lock`, `pthread_mutex_trylock`, `pthread_rwlock_rdlock`,
`pthread_rwlock_wrlock` and `pthread_cond_wait` to wrappers that count when armed and then call the
real function. Do not interpose `os_unfair_lock_lock` (Pitfall 10). Header comment: test-only,
macOS only, why the tuples must live in a linked dylib (tuples in the main executable are ignored),
and that `juce::SpinLock` is invisible to it (covered by the Plan 05-03 source-scan rule).
