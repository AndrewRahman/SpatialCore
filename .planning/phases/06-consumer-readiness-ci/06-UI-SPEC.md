# Phase 06 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Contract Verdict: NO VISUAL CHANGE

SpatialCore is a JUCE C++ audio library, not a web frontend. Phase 06 (Consumer Readiness & CI)
delivers an umbrella header, CI workflows, coverage tooling, a gains-misuse counter, regression
tests and documents. **Nothing a user of SpatialCore, OpenSpatialDelay or the SpatialCoreDemo app
sees, hears-as-a-screen, or clicks changes in this phase.**

The UI safety gate fired because Plan 06-01 added `include/SpatialCore/SpatialCoreUI.h` and
`tests/UI/UmbrellaUITests.cpp` (UI-named paths). Both are include plumbing and a test; neither
draws anything.

**The contract this phase locks:**

1. The existing design system is inherited **unchanged**: `SMLLookAndFeel` (seven embedded
   typefaces), JetBrains Mono inside `SpatialMapComponent`, the existing colours and the existing
   control sizes. This spec invents no new token.
2. No file under `include/SpatialCore/UI/` or `src/UI/` may change in any way that alters
   rendering. At phase end, `git diff 7eb625b -- include/SpatialCore/UI src/UI` must print nothing.
   (`7eb625b` is the phase-start commit; the tree has no UI-directory change since BASE today.)
3. The only new pixels the phase may produce are in the consumer harness editor (Plan 06-04),
   which is a test template, ships to no one, and may use only what the existing library already
   draws (see "Harness Editor Contract").

## Typography

Inherited from `src/UI/` as measured on 2026-10-17 (`grep` for `withHeight` and `makeFont`). No
size, weight or line height is added, removed or changed by Phase 06. The existing system uses
more than four sizes because it predates this contract; Phase 06 does not rationalise it.

| Role | Size | Weight / face | Where it comes from |
|------|------|---------------|---------------------|
| Map pole labels, small caption | 9 px | JetBrains Mono Regular | `SpatialMapComponent.cpp:268` |
| Section label, trajectory caption, object number | 10 px | JetBrains Mono Medium/Bold, DM Sans (OSC labels, kerning 0.08 to 0.12) | `ObjectPanel.cpp`, `OSCSectionComponent.cpp`, `SpatialMapComponent.cpp` |
| Slider text box font, map minor text | 11 px | JetBrains Mono Regular | `SMLLookAndFeel.cpp:390` (`createSliderTextBox`), `SpatialMapComponent.cpp` |
| Slider value label as painted by `drawLabel` | 12 px | JetBrains Mono Regular | `SMLLookAndFeel.cpp:323` |
| Combo, popup menu, text button | 13 px | DM Sans Regular | `SMLLookAndFeel.cpp:49-61` |
| Map cardinal / title text | 14 px (kerning 0.2) | JetBrains Mono Medium | `SpatialMapComponent.cpp:310` |
| Preset browser title | 28 px | DM Sans Bold (documented exemption, DATA-02, D-22 rejected) | `PresetBrowser.cpp:150` |

Weights in use: Regular, Medium, Bold (`SMLLookAndFeel::getTypefaceForFont` maps any bold-flagged
font to DM Sans Bold, everything else to DM Sans Regular). Line heights are JUCE-computed from
font height; no ratio is declared. Do not edit any of these in Phase 06.

## Harness Editor Contract

The one new on-screen surface (Plan 06-04, `HarnessEditor` in `examples/harness/src/HarnessPlugin.cpp`).
It exists to prove a consumer can include `<SpatialCore/SpatialCoreUI.h>`, create the shared
look-and-feel, and paint the map. It is never shipped, never in SpatialCore's own build, and
carries no product design.

| Property | Contract |
|----------|----------|
| Content | Exactly one `spatialcore::SpatialMapComponent` of `kNumObjects` (2) filling the editor. No buttons, labels, sliders, menus or text of its own |
| Size | 420 x 420 px, no margin (Plan 06-04 Task 2) |
| Look-and-feel | One `juce::SharedResourcePointer<spatialcore::SMLLookAndFeel>`, applied with `setLookAndFeel`; `setLookAndFeel (nullptr)` in the destructor (D-12 guidance, the shared-instance pattern the integration guide teaches) |
| Colour, type, spacing | Whatever the library already draws. The harness may not set a colour, font or bounds override |
| Update rate | 30 Hz timer copies the two object positions into the map; positions only, no other state |
| Interaction | None required. Map drag is inherited library behaviour and is not tested here |
| Accessibility | Inherited from the library. The harness adds no focus order or labels (no controls) |
| Verification | Headless: `createEditorIfNeeded()`, `setSize (420, 420)`, `createComponentSnapshot`; FAIL unless the image is valid and not one flat colour. Delete the editor before the processor |

The harness editor must not be used as visual evidence of the product's look. Product screens are
judged against the Phase 04 approved demo screenshots, not this editor.

## Executor Guardrails (what this contract forbids)

- Do not edit anything in `include/SpatialCore/UI/` or `src/UI/` in Phase 06. The one allowed
  exception is a scratch mutation in 06-03 Task 3 that is restored before the task ends.
- `SpatialCoreUI.h` contains only the ten `#include` lines, a comment, and `#pragma once`: no
  types, macros, `using` declarations or default look-and-feel side effects.
- Do not add fonts, colours, sizes or a spacing token file "for the harness".
- Do not add golden screenshots or UI baselines in this phase.
- Coverage instrumentation flags must apply only when the coverage option is on; a normal Debug or
  Release build renders identically.
- Do not add a UI tool, preset or registry (shadcn, Tailwind, web assets).
