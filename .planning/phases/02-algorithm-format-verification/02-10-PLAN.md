<objective>
Close UAT gap G-02-10: the full test suite must pass in a Release build, the build type CI uses.
Today one test, `[ambi-pin]`, fails in Release on Apple Silicon only.

Root cause (`.planning/debug/ambi-pin-release-tolerance.md`): not a decoder defect. `[ambi-pin]`
compares two separately compiled float copies of the same decoder (the library's
`AmbisonicsCodec::getDecodeMatrix` and the test's verbatim pre-change `referenceAmbiDecode`) with a
bound of one part per million. At -O3 on arm64, clang fuses different terms of the E*E^T sum in
each translation unit, so the two copies round differently; because E*E^T is singular and only the
0.01 Tikhonov term makes it invertible (condition number 501 to 1786), that rounding shows up as up
to 5.3e-6 in the decode. Debug (-O0) is bit-identical, which is why the Debug-only phase gates
never saw it. The bound came from RESEARCH F10's Debug-grade "worst 0" measurement plus an
unmeasured margin; it was never derived.

Fix (test-side only, per D-09's own wording "within float tolerance"): replace the bound with one
derived from the float noise floor, record the derivation beside the number, add a
double-precision anchor that re-measures that noise floor on every run, prove the bound passes in
both build types and still catches a +0.1% Tikhonov-epsilon change, and make the phase gate run
the suite in Release too so this class of failure cannot hide again.

Purpose: VERIFY-01 / EXTR-03's decode pin (D-09) must be true on the build that ships, not only on
the Debug build. Output: one corrected test, a gitignored Release tree, a Release gate in the
validation contract and in the codebase testing notes, three deferred notes, and a SUMMARY with a
plain-English account and one yes/no question for the user.
