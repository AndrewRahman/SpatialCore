Close UAT gap G-02-2: on height layouts, a source between 0 and -30 degrees must pan as ITU-R
BS.2127 (EAR) does — the horizon pan holds, with no lean and no side flip. The user chose option B
in UAT (change the panning, not the docs).

Root cause (`.planning/debug/below-horizon-band-vs-ear.md`): `appendLowerHemisphereTriplets` emits
each ear-level/-30 degree trapezoid as all four overlapping triangles of a planar quad. The
minimum-sum rule in `computeVBAPGains3D` then breaks an exact (or 1-2 ULP) tie between two
mirror-image triangles, so enumeration order and float noise pick the lean side. EAR pans each
trapezoid as one QuadRegion, which (with the -30 copies downmixed 1:1 onto their ear-level speakers)
collapses to the elevation-independent 2D pair pan at the source azimuth. No triangulation can
reproduce that; one pair-pan region per neighbouring ear-level pair does (diagnosis prototype:
residual <= 4.4e-7 against ear, above-horizon bit-identical on 259,920 points).

Task 1 (tracer) replaces the trapezoid triangles with pair-pan wedges and orders the lower tiers, and
proves it end to end on the user's own probe (7.1.4, azimuth 60, elevation 0 to -30) through
RenderEngine and VBAPAlgorithm. Task 2 expands the proof to all 8 height layouts: ear 2.1.0 band
pins, an independent pair-pan property test with a no-tie check, and the band continuity bound
tightened from 0.12 to the 0.01 cap bound.

promise. D-05 scope is unchanged (VBAP family only). Requirement EXTR-01.
