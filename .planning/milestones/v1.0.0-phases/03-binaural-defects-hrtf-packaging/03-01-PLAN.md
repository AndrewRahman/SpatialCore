## Ground rules for this plan

- **The user is not a programmer.** Claude runs every configure, build and test. Nothing here asks
  the user anything.
- **Diff base:** `BASE` = the commit HEAD pointed at when this plan started (record it in the SUMMARY); every "unchanged" check compares `BASE..HEAD`.
- **Build trees.** Debug: `build/` (binary `./build/tests/SpatialCoreTests`). Release:
  `build-release/` (already configured by Phase 2 Plan 02-10 with offline FetchContent sources in
  `build/_deps`); rebuild with `cmake --build build-release --target SpatialCoreTests -j8` and run
  the full Release suite with `ctest --test-dir build-release/tests --output-on-failure` (the
  `/tests` directory matters).
- **One plan at a time (binding for every Phase 3 plan).** Phase 3 executes serially: each plan's
  `wave` is one higher than the plan before it, so no two Phase 3 plans ever run together. Every plan
  builds in the same `build/` and `build-release/`, so plans running together would race on one
  build tree and compile each other's uncommitted edits; one plan per wave rules both out. A plan
  starts from the committed tree its predecessor left and commits its own work before the next plan
  starts. Extra trees a plan needs live under `/tmp` with a plan-specific name.
- **Fresh checkout:** if `build-release/CMakeCache.txt` is missing (for example in a fresh executor
  worktree), configure it once after `build/` exists, with the settings the existing tree uses:
  `cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release -DFETCHCONTENT_FULLY_DISCONNECTED=ON -DFETCHCONTENT_SOURCE_DIR_JUCE="$PWD/build/_deps/juce-src" -DFETCHCONTENT_SOURCE_DIR_CATCH2="$PWD/build/_deps/catch2-src" -DFETCHCONTENT_SOURCE_DIR_MYSOFA="$PWD/build/_deps/mysofa-src"`.
- **Catch2 v3** exits non-zero when an assertion fails and when a filter matches no test case; every
  verify still names "No test cases matched" as a failure signal.
- **Expected Debug noise, not failures:** libmysofa parse traces on stderr (lines starting with
  `/Users/`), `JUCE Assertion failure in BinauralRenderer.cpp` lines whenever KEMAR (IR 558) runs at
  a maximum block of 557 or less (the audio-thread resize Plan 03-03 removes), and the
  `juce_LeakedObjectDetector.h` assertion at exit (SharedFFTCache false positive, deferred).
- **Baseline before this plan:** Debug 208/209 (only `HutubsPP2Tests.cpp:47`, fixed by Plan 03-02,
  which runs next), Release 209/209.
- **Style:** match `tests/Engine/RenderEngineTests.cpp` and `tests/Binaural/HutubsPP2Tests.cpp`:
  JUCE spacing (`f (x)`, `CHECK (...)`), 4-space indent, anonymous namespace for file-local
  helpers, `using namespace spatialcore;`, shared helpers in `namespace spatialcore::test`.
- **Profile files (D-07 numbering):** 1 `sadie_d2_ku100.sofa` (IR 256 at 48 kHz), 2
  `cipic_subject_003.sofa` (218), 3 `hutubs_pp2.sofa` (279), 4 `bernschuetz_ku100.sofa` (128),
  5 `mit_kemar_large_pinna.sofa` (558). 0 is Simple (Woodworth).
- **Runtime budget:** each tag under about 10 s in Debug except `[loudness]` and 5-profile sweeps
  (under about 30 s). Load SADIE (36 MB) only where the profile itself is the point.
