## Ground rules for this plan

- **The user is not a programmer.** Claude runs every configure, build and test; nothing here asks the user anything.
- **Diff base:** `BASE` = the commit HEAD pointed at when this plan started (record it in the SUMMARY).
- **One plan at a time.** Phase 4 runs serially, one plan per wave, as Phase 3 did: every plan builds in
  the same `build/` and `build-release/`, so two plans at once would race on one build tree and compile
  each other's uncommitted edits.
- **Build trees.** Debug `build/` (binary `./build/tests/SpatialCoreTests`), Release `build-release/`.
  The worktree has neither yet; Task 1 creates both. Dependency sources: set
  `DEPS=/private/tmp/sc-kemar-only-validate/_deps` (cached JUCE 9.0.0, Catch2 v3.7.1, libmysofa v1.3.5,
  verified by the researcher). If `$DEPS/juce-src/CMakeLists.txt` exists, configure both trees with
  `-DFETCHCONTENT_FULLY_DISCONNECTED=ON -DFETCHCONTENT_SOURCE_DIR_JUCE="$DEPS/juce-src" -DFETCHCONTENT_SOURCE_DIR_CATCH2="$DEPS/catch2-src" -DFETCHCONTENT_SOURCE_DIR_MYSOFA="$DEPS/mysofa-src"`.
  If it does not, configure `build/` with no overrides (FetchContent downloads into `build/_deps`) and
  then use `DEPS="$PWD/build/_deps"` for `build-release/`. Debug adds
  `-DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON`; Release adds `-DCMAKE_BUILD_TYPE=Release`.
  Configure stops with "git lfs pull" if a SOFA file is still an LFS pointer; run `git lfs pull` then.
- **Full gates build every target** (`cmake --build build -j8`, `cmake --build build-release -j8`), never
  `--target SpatialCoreTests` alone before `ctest`: once Plan 04-05 adds a second Catch2 executable, an
  unbuilt one registers a failing `*_NOT_BUILT` test (RESEARCH Pitfall 7). Tagged quick runs may build one target.

- **Expected Debug noise, not failures:** the `juce_LeakedObjectDetector` assertion at exit (SharedFFTCache
  false positive, deferred) and libmysofa trace lines starting with `/Users/`.
- **Style:** as `tests/Engine/RenderEngineTests.cpp`: JUCE spacing (`f (x)`, `CHECK (...)`), 4-space
  indent, file-local helpers in an anonymous namespace, `using namespace spatialcore;`, shared test
  helpers in `namespace spatialcore::test`.
- **Threads:** OSC code runs on the message thread; nothing in this plan touches `RenderEngine`'s audio path (DR-1).
- **UDP ports for tests (phase table):** 9720-9729 this plan, 9730-9749 Plan 04-02, 9750-9769 Plan 04-03,
  9790-9799 the demo self-test (Plan 04-07). Never 4001-4003, 9000 or 9700-9702 (ADM-OSC defaults and
  existing tests).
- **Baseline before Phase 4:** Debug and Release 266/266 (v1.0.0 milestone audit).

## Research numbers the tests are built on (04-RESEARCH.md Pattern 2, measured on this tree)

One object, 48 kHz, 4 blocks of 64, mono `0.5 * sin (0.2 n)`, distance 0.5, elevation 0, both flags set,
RMS of the last block: Binaural (Simple Woodworth, no profile) az +90 L 0.1557 / R 0.0470 (3.31),
az +45 L 0.1557 / R 0.0668, az 0 equal, az -90 L 0.0470 / R 0.1557. Quad az +45 ch0 0.3503 others 0,
az -45 ch1, az +135 ch2. The Simple path reads distance from `objGains` (`DirectBinauralAlgorithm`
folds `1 / max (0.1, 4d + 0.25)` into both ears) and never reads `distGainPerSample`; the surround path
multiplies by `distGainPerSample`. Lateral cue is `sin (az) * cos (el)`, so elevation 75 at azimuth +90
keeps about a quarter of the interaural level difference (predicted L/R about 1.3).

that calls `engine.prepare (kSampleRate, kBlockSize)` and `engine.setOutputFormat (format)`; a mono buffer
filled with `0.5f * std::sin (0.2f * n)` for n in [0, 64); a unity tap-fade buffer; one distance-gain
buffer per object slot, refilled on every render with `distanceAttenuation (object distance)` (what a
consumer supplies for the surround, HRTF and Ambisonics paths; the Simple binaural path ignores it and
folds distance into its own gains, as `renderSimpleBinauralWoodworth` in read_first shows). Methods:
`setObject (int index, float azDeg, float elDeg, float dist, bool enabled = true)`;
`mergeObject (int index, float azDeg, float elDeg, float dist)` that overwrites only the axes that are
not NaN (the consumer rule documented on `ADMOSCReceiver::Listener::admPositionReceived`);
`ObjectState object (int index) const`; `std::array<float, MAX_SPEAKERS> renderRms (int blocks = 4)`
that builds `RenderSources` (mono, tap-fade and distance-gain pointers, `objectLive`, `objects`) for the
enabled slots, builds a fresh `RenderBlockContext` per block with only `sampleRate`,
`engineComputesGains = true` and `engineDerivesDispatch = true` set (D-18: leave every dispatch field at
its default, the engine fills them from its own layout), renders `blocks` blocks into `MAX_SPEAKERS`
zeroed channel buffers with `numOutChannels` passed to `renderBlock`, and returns the RMS of each
channel over the last block; `float leftRightRatio (int blocks = 4)` returning rms[0] divided by
`std::max (rms[1], 1e-9f)`; `static int loudestChannel (const std::array<float, MAX_SPEAKERS>& rms, int numChannels)`.
All buffers are members sized in the constructor. A short header comment says this is the consumer
wiring a plugin writes (D-12) and why both flags are set (D-18, INTG-02 opt-out path).
