## Ground rules for this plan

- **The user is not a programmer.** Claude runs everything. Nothing here needs a decision.
- **Outward action (the only one):** `git push origin HEAD` pushes the current work branch (never `main`) so GitHub holds the commit under test. Never force-push; if the push is rejected, stop and report. A pushed branch can be deleted later with `git push origin --delete <branch>`.
- **What comes from where:** the harness template is copied from this working tree; SpatialCore inside the consumer comes from GitHub at the pushed commit. So library changes must be committed and pushed before the script is re-run; template changes need not be.
- **Diff base:** `BASE` = HEAD at plan start. **One plan at a time.** The consumer builds live in `/tmp/sc-p6-harness*` (set `HARNESS_WORK_DIR`), never in the repo.
- **Dependency reuse:** pass `-DFETCHCONTENT_SOURCE_DIR_JUCE=$PWD/build/_deps/juce-src -DFETCHCONTENT_SOURCE_DIR_MYSOFA=$PWD/build/_deps/mysofa-src` (absolute paths of this worktree's Debug tree) through the script's `--` pass-through so the consumer does not download JUCE again; the OSD-like run still downloads libmysofa v1.3.2.
- **New files are LF.** The script is committed executable (mode 100755).
- **Style:** JUCE conventions (`juce::ScopedNoDenormals` first in processBlock, every buffer sized in prepareToPlay, message-to-audio values through `std::atomic`, nothing allocated, locked or logged in processBlock). This is the copy-paste reference for OSD, so comment the why of each facade call briefly.
