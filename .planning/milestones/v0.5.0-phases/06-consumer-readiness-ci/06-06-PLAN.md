## Ground rules for this plan

<!-- planner-discipline-allow: continue-on-error -->
<!-- planner-region-allow: continue-on-error -->

- **The user is not a programmer and has only a Mac.** Claude does everything through GitHub's hosted Linux and Windows machines; never ask the user to run anything on Windows or Linux.
- **Outward actions (only these):** `git push origin HEAD` of the work branch and `gh workflow run` dispatches on it (`-f realtime=false` during bring-up). Never push to `main`; never change repository settings.
- **Bring-up order per job:** add it with `continue-on-error: true`, push, read the run, fix, repeat; remove `continue-on-error` when it is green, push, and see it green once more without it.
- **Fix rules:** root-cause every failure. A test that hard-codes something platform-specific (a path, a port, a macOS-only API, a float bound tighter than another libm allows) is fixed in the test only when the test's intent is preserved and the macOS result is unchanged, with the reason written beside the change; a library defect is fixed in the library with a test that fails without the fix. After any library change run the full local gate on this Mac before pushing (zero regressions on macOS). Never widen a golden or tolerance without recording the measured Linux value and why the old bound was macOS-specific.
- **Stop rule (context budget):** if Linux and Windows together show more than five distinct root causes, or any fix would change macOS output, stop after recording what was found and return a checkpoint with a plain-English summary so the work can be split; do not hide the remainder behind continue-on-error.
- **Repository:** `-R AndrewRahman/SpatialCore` on every `gh` call. Identify runs by `--commit "$(git rev-parse HEAD)"`.
- **Diff base:** `BASE` = HEAD at plan start. One plan at a time (the local gate uses the shared trees).
