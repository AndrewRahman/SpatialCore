## Why a blocking human gate leads this plan

RESEARCH's Package Legitimacy Audit returned **SUS** for numpy, scipy and ear — for missing
registry metadata, not malicious signals. Per the package-legitimacy rule every `[SUS]` package
gets a `checkpoint:human-verify` with `gate="blocking-human"` before it is installed or used; that
gate is never auto-approved, including in auto mode. One checkpoint covers the single venv, as
RESEARCH recommends. A venv already exists at `.context/venv` (gitignored) because research
installed the packages **without** human vetting, so the gate precedes any use of it, not merely a
fresh install.
