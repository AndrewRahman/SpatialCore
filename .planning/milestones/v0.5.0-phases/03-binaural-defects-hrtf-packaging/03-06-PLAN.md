<objective>
Move profile switching into SpatialCore behind one call (D-04): `RenderEngine::setHRTFProfile (int)`.
It returns at once, a worker thread resolves and loads the profile into the renderer the audio
thread is not using, and the audio thread picks it up from an atomic mailbox at a block boundary and
crossfades with the existing machinery. Failures keep the current sound and report a readable status.
This replaces the consumer glue OSD runs on its message thread today
(`loadHRTFProfileIntoRenderer` / `loadHRTFProfile` / `timerCallback`, OSD `PluginProcessor.cpp`
about 1495-1600).

Purpose: DATA-01's "owns profile switching end to end behind one engine call", D-04, D-05, D-06,
D-09/D-11 at engine level, and criterion 3 through the engine. The proof under real concurrency (a
render thread plus a switching thread, shutdown mid-load, a ThreadSanitizer run) is Plan 03-07,
split out of this plan to keep each within the context budget. Click-free timing at small blocks and
the Simple <-> HRTF crossfade are Plan 03-09; this plan keeps today's renderer crossfade.

Output: the public switching API, the loader and mailbox, and the engine-level switching tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| message thread → loader thread | Requests and the folder override cross by atomics and a lock (lock off the audio thread only). |
