<objective>
Fix SpatialCore#15 on the Simple (Woodworth) binaural path. Today the Simple path is a pair of
broadband gains driven by `lateral = sin az cos el`, so a source behind, in front, overhead and
underfoot all sound identical (0.00 dB difference, measured). Add the lightweight spectral cues D-01
chose: a rear head-shadow cut and a pinna-style elevation cue, as three fixed filter branches blended
by position, on the engine's Simple path (the algorithm stays stateless). The front half at ear level
stays bit-identical, so OSD's familiar default sound does not move.

Purpose: criterion 1 for the Simple path (the HRTF path is already proven by Plan 03-01), closing
the test side of SpatialCore#15 (D-03). The audible change ships with an OSD release note, not a
switch (D-02; the note is recorded by Plan 03-10).

Output: one new public header with the pure weight function and the filter table, the cue bank in
`RenderEngine`, and the `[bug01]` Simple tests.
</objective>

## Ground rules for this plan

- **Diff base:** `BASE` = the commit HEAD pointed at when this plan started (record it in the SUMMARY).
- **The user is not a programmer.** Claude runs everything; nothing is asked. The headphone
  listening check is ROADMAP backlog 999.4 and is not a gate (D-03).
- **Build trees and commands** as in Plan 03-01.
- **Do not edit** `tests/CMakeLists.txt` or `tests/Binaural/BinauralMetrics.h` (Plan 03-01 owns
  them).
- **One plan at a time** (Plan 03-01 ground rules): this plan runs after Plan 03-03 (convolver,
  renderer) has committed and before Plan 03-05 (CMake, HRTF data), never alongside either. Until
  Plan 03-06 starts, this plan is the only editor of `RenderEngine.h` / `RenderEngine.cpp`.
- **Conventions:** az 0 = front, positive azimuth = left, el 0 = ear level, positive = up
  (`src/Core/SpatialMath.cpp:12-17`). `RenderSources::objects` positions are degrees and are
  sanitised (hold-last-good) by `sanitizeSources` before any render path runs. OSD fills
  `objects[]` for every path every block (verified at OSD 30391cd `PluginProcessor.cpp:3200-3203`).
- **Fast-math:** `RenderEngine.cpp` already includes `FloatSemanticsGuard.h`; keep every finiteness
  test in that TU, never in the new header.
- **Filter design note (planner analysis):** in float, `cos (degreesToRadians (90.0f))` is
  -4.37e-8, so without a snap the rear weight at az +-90 would be 4.37e-8 and break the bit-exact
  identity at the sides. `kSimpleCueWeightEpsilon = 1e-6f` handles it.
- **Measured design numbers (research):** Rear 4.49 dB RMS / 11.6 dB max at full weight, Up 2.70 /
  8.4, Down 2.04 / 5.2; DC 0.000 +- 0.001 dB. A weaker Up (+8 dB, no shelf) gave only 2.20 dB RMS,
  which is why the Up branch has the shelf. If a design misses a bound below, tune only within the
  literature-consistent shape (frequencies within +-20%, gains within +-3 dB of the table) and
  record the final values; never lower a test bound.
